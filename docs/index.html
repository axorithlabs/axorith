Getting Started

Introduction

Axorith is a Digital Life System that automates your entire digital workspace. One click to deep work. One click to gaming mode.

What is Axorith?

Axorith was born from a simple, powerful observation: the modern digital workspace is fundamentally broken.

The very tools meant to help us have become the primary source of friction. Existing applications only treat the symptoms — they are features within the chaos.

Axorith is not another app. It's a remote control for your digital life. We believe you shouldn't spend mental energy setting up your environment.

Alpha Release

Axorith is currently in alpha. Features may change, and you might encounter bugs. We'd love your feedback on Discord!

Core Philosophy

⚙️

You Are In Control, Not The Machine

Define the rules for your focus, codifying your entire workflow into reusable, one-click launchers.

🧩

Radical Modularity

The entire system is built on plugins. Axorith provides the conductor's podium; you choose the instruments.

🛡️

Unmatched Stability

Client-Server architecture means if the UI crashes, your focus session keeps running.

Installation

Axorith is currently available for Windows, with macOS and Linux support coming soon.

Windows

  1. Download the latest installer from GitHub Releases
  2. Run Axorith-Setup-x.x.x.exe
  3. Follow the installation wizard
  4. Launch Axorith from the Start Menu
Antivirus Warning

Some antivirus software may flag Axorith due to its use of Windows APIs. This is a false positive. See FAQ for details.

System Requirements

  • Windows 10 version 1903+ (64-bit)
  • .NET 10 Runtime (bundled)
  • 4 GB RAM minimum
  • 100 MB disk space

Quick Start

Get up and running in under 5 minutes.

1

Launch Axorith

After installation, Axorith starts automatically with an empty preset list.

2

Create Your First Preset

Click + New Preset and name it "Deep Work" or "Coding Mode".

3

Add Modules

Click Add Module and choose App Launcher, Site Blocker, or Spotify.

4

Configure & Save

Set up each module (apps to launch, sites to block) and save.

5

Start a Session

Click Start on your preset. Enter your flow state.

Sessions

A Session is an active instance of a preset. When you start a session:

  1. Axorith loads the preset configuration
  2. Instantiates each configured module
  3. Validates all module settings
  4. Calls OnSessionStartAsync on each module
  5. Monitors the session until you stop it

Sessions run in the background Host process, so they survive UI crashes.

Presets

A Preset is a saved configuration that defines:

  • Which modules to activate
  • Settings for each module
  • Optional scheduling rules (Pro feature)

Presets are stored as JSON files in %AppData%/Axorith/presets/.

Modules

Modules are plugins that extend Axorith's functionality. Each module:

  • Implements the IModule interface
  • Defines its own settings and actions
  • Responds to session lifecycle events

Modules are loaded from build/modules/ directory at startup.

Settings & Actions

Settings

Settings are persistent configuration values that users can modify. They use the reactive Setting<T> class.

C# — Defining a Setting
public Setting<string> PlaylistUri { get; } = new(
    key: "playlistUri",
    label: "Playlist URI",
    defaultValue: ""
);

Actions

Actions are one-time commands that users can trigger. They don't persist state.

C# — Defining an Action
public IAction SkipTrack { get; } = new Action(
    key: "skipTrack",
    label: "Skip Track",
    execute: async () => await _spotify.SkipAsync()
);

App Launcher Module

Launches applications when a session starts.

Settings

  • applications — List of executable paths or names to launch
  • arguments — Optional command-line arguments
  • workingDirectory — Working directory for launched apps

Site Blocker Module

Blocks distracting websites during focus sessions via browser extension.

Settings

  • blockedDomains — List of domains to block
  • blockSubdomains — Whether to block subdomains (default: true)

How It Works

Uses Native Messaging to communicate with a browser extension. No admin rights required.

Spotify Player Module

Controls Spotify playback during sessions.

Settings

  • playlistUri — Spotify URI of playlist to play
  • shuffle — Enable shuffle mode
  • volume — Initial volume (0-100)

Actions

  • play — Resume playback
  • pause — Pause playback
  • skip — Skip to next track

IDE Launcher Module

Launches JetBrains IDEs with specific projects.

Settings

  • ide — IDE to launch (rider, idea, webstorm, etc.)
  • projectPath — Path to project to open

Architecture

Axorith uses a client-server architecture for stability and flexibility.

Architecture Diagram
┌─────────────────┐     gRPC      ┌─────────────────┐
│  Axorith.Client │ ◄──────────► │  Axorith.Host   │
│  (Avalonia UI)  │              │ (ASP.NET Core)  │
└─────────────────┘              └────────┬────────┘
                                          │
                                          ▼
                                 ┌─────────────────┐
                                 │  Axorith.Core   │
                                 │ (Session Engine)│
                                 └────────┬────────┘
                                          │
                    ┌─────────────────────┼─────────────────────┐
                    ▼                     ▼                     ▼
           ┌───────────────┐    ┌───────────────┐    ┌───────────────┐
           │ Site Blocker  │    │    Spotify    │    │  App Launcher │
           └───────────────┘    └───────────────┘    └───────────────┘

Key Components

  • Axorith.Client — Avalonia UI, ReactiveUI MVVM
  • Axorith.Host — ASP.NET Core gRPC server
  • Axorith.Core — Session engine, module orchestration
  • Axorith.Sdk — Contracts for module development

IModule Interface

The core contract every module must implement.

C# — IModule Interface
public interface IModule : IDisposable
{
    // Return all configurable settings
    IReadOnlyList<ISetting> GetSettings();
    
    // Return all available actions
    IReadOnlyList<IAction> GetActions();
    
    // Called once after instantiation
    Task InitializeAsync(CancellationToken ct);
    
    // Validate settings before session start
    Task<ValidationResult> ValidateSettingsAsync(CancellationToken ct);
    
    // Called when session starts
    Task OnSessionStartAsync(CancellationToken ct);
    
    // Called when session ends
    Task OnSessionEndAsync(CancellationToken ct);
    
    // Optional: Custom settings UI
    Type? CustomSettingsViewType { get; }
    object? GetSettingsViewModel();
}

ISetting Interface

Reactive settings that automatically sync with the UI.

C# — ISetting Interface
public interface ISetting
{
    string Key { get; }
    string Label { get; }
    string? Description { get; }
    
    // Reactive properties
    IObservable<bool> IsVisible { get; }
    IObservable<bool> IsReadOnly { get; }
    IObservable<object?> ValueAsObject { get; }
    
    // Serialization
    void SetValueFromString(string? value);
    string? GetValueAsString();
    
    // Validation
    ValidationResult Validate();
}

Built-in Setting Types

  • Setting<string> — Text input
  • Setting<int> — Number input
  • Setting<bool> — Toggle/checkbox
  • Setting<List<string>> — List of strings

gRPC API

Axorith uses gRPC for client-server communication. All contracts are defined in Axorith.Contracts.

Connection

The Host listens on http://localhost:5050 by default (HTTP/2, no TLS for local development).

Proto — Service Definitions
service SessionService {
  rpc StartSession(StartSessionRequest) returns (StartSessionResponse);
  rpc StopSession(StopSessionRequest) returns (StopSessionResponse);
  rpc GetActiveSession(GetActiveSessionRequest) returns (SessionSnapshot);
  rpc StreamSessionEvents(StreamRequest) returns (stream SessionEvent);
}

service PresetService {
  rpc GetPresets(GetPresetsRequest) returns (GetPresetsResponse);
  rpc CreatePreset(CreatePresetRequest) returns (PresetResponse);
  rpc UpdatePreset(UpdatePresetRequest) returns (PresetResponse);
  rpc DeletePreset(DeletePresetRequest) returns (DeletePresetResponse);
}

service ModuleService {
  rpc GetAvailableModules(GetModulesRequest) returns (GetModulesResponse);
  rpc UpdateSetting(UpdateSettingRequest) returns (UpdateSettingResponse);
  rpc ExecuteAction(ExecuteActionRequest) returns (ExecuteActionResponse);
}

Session Service

Manages session lifecycle.

StartSession

Starts a new session from a preset.

  • Request: presetId (GUID)
  • Response: sessionId, status

StopSession

Stops the currently active session.

StreamSessionEvents

Server-streaming RPC that pushes session events (started, stopped, module status changes).

Preset Service

CRUD operations for presets.

GetPresets

Returns all saved presets.

CreatePreset

Creates a new preset with the given configuration.

UpdatePreset

Updates an existing preset.

DeletePreset

Deletes a preset by ID.

Module Service

Module discovery and runtime control.

GetAvailableModules

Returns all loaded module definitions with their settings schemas.

UpdateSetting

Updates a setting value for a module instance in the active session.

ExecuteAction

Executes an action on a module instance.

FAQ

Is Axorith free?

Yes, the core application with all modules is free. We charge for cloud features (sync, scheduling, team collaboration).

Why is my antivirus flagging Axorith?

Axorith uses Windows APIs for process monitoring. Some antivirus software flags this as suspicious. Add Axorith to your exclusions list.

Does Site Blocker require admin rights?

No. It uses Native Messaging to communicate with a browser extension — a secure, standard approach.

What happens if the UI crashes?

Your session keeps running in the background Host process. Simply restart the UI and reconnect.

Can I create my own modules?

Yes! See the Creating Modules guide.

Troubleshooting

Host won't start

  • Check if port 5050 is available
  • Check logs in %AppData%/Axorith/logs/
  • Ensure .NET 10 runtime is installed

Site Blocker not working

  • Ensure the browser extension is installed
  • Check that Native Messaging host is registered
  • Restart the browser after installation

Module not loading

  • Verify module.json is valid JSON
  • Check that the assembly path is correct
  • Ensure the module targets the correct platform
